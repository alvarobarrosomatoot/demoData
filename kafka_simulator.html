Messages are dispatched asynchronously using timed intervals.
The interval between each message = 60000 / throttle ms.

What is Apache Kafka?

Apache Kafka is a distributed event streaming platform designed for high-throughput, fault-tolerant, real-time data pipelines. Think of it as a highly scalable message queue that retains messages on disk, allowing multiple consumers to read the same data independently.


Unlike traditional message brokers (RabbitMQ, ActiveMQ), Kafka:

  • Persists messages — consumers can replay data.
  • Scales horizontally — add brokers to increase throughput.
  • Decouples producers & consumers — they don't need to know about each other.

Key Concepts

  • Topic — A named stream of records (e.g. consent_events). Messages are published to topics.
  • Partition — Topics are split into partitions for parallelism. Each partition is an ordered, immutable log.
  • Offset — A unique sequential ID for each message within a partition. Consumers track their position via offsets.
  • Producer — An application that publishes messages to a topic.
  • Consumer / Consumer Group — Applications that read messages. Within a group, each partition is consumed by exactly one member.
  • Broker — A Kafka server that stores data and serves clients.

Kafka in UCPM / Consent Management

In a Universal Consent & Preference Management (UCPM) context, Kafka acts as the backbone for consent signal distribution:


  • Ingestion — Consent signals (opt-in, opt-out) are collected via APIs/SDKs and published to a Kafka topic.
  • Fan-out — Multiple downstream systems (CRM, data warehouse, marketing tools) each have their own consumer group, receiving every signal independently.
  • Replay — If a system goes down, it can replay from its last committed offset — no data loss.
  • Audit trail — Kafka retains consent events for configurable periods, providing a compliance-ready log.
  • Real-time — Consumers process signals within milliseconds, ensuring downstream systems are always in sync with the user's latest preferences.
